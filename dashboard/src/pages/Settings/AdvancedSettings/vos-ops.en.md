### Use VOS Operations

Open **Admin → Application Settings → VOS Operations** and select **Authorize diagnostics**. A VOS super administrator can view installed applications, workflow status, application containers, recent logs, diagnostic summaries, Docker-published ports and images. To use the read-only `vos_diagnostics` tool in your experts, select **Allow my experts to read diagnostics during this grant** before authorizing. End the grant in the operations panel or sign out of v-Octop. Authorization lasts up to 15 minutes.

For a restart, stop or cleanup, review the preview and type the complete target ID. Each preview expires after 60 seconds and can be executed once. Restart applies to installed apps. Stop applies to running or restarting containers from older versions of an installed or stopped app. Eligible old containers in `created` or `exited` state can be removed without deleting volumes. Only unreferenced, untagged images without repository digests can be removed. The running v-Octop app is protected from these container and restart actions.

### API

Use the same VOS origin and the base path `/app/com.ictrek.v-octop/__va/vos-ops`. Send the signed-in browser cookie and `X-VA-Ops: 1`. Requests with a cross-origin fetch context are rejected. JSON POST requests use `Content-Type: application/json`. The grant obtained from `authorize` goes in `X-VA-Ops-Grant` for subsequent requests. The grant belongs to the browser session. Each request checks the current VOS token's `is_super_admin` permission. Responses use JSON and disable caching.

App IDs are 1–128 letters, digits, dots, underscores or hyphens and start with a letter or digit. No endpoints accept caller-supplied Docker paths. Lists can be empty.

**Inventory.** App rows contain `appId`, `installationId`, `version`, `state`, `lastError` (empty when absent), and `restartable` (boolean). Container rows contain `id`, `name`, `image`, `imageId`, `state`, `status`, `stack`, `ports`, `stoppable` and `cleanup`. The final two are eligibility booleans. A port entry contains numeric `hostPort`, `containerPort`, and strings `protocol` and `address`. The published-port list also contains `container` and nullable `appId`. It describes Docker host-port mappings. Image rows contain `id` and `bytes`. Unused untagged images also have `created` (Unix seconds). Unreferenced tagged images have `tags` and `digests` (string arrays).

**Logs.** The default scan reads the last 150 records. Optional `since` and `until` accept RFC 3339 timestamps or a positive span with units `ms`, `s`, `m`, `h`, or `d` relative to the current time. Use `after` with the previous response's `next` UTC timestamp as an exclusive cursor instead of `since`. `pattern` is a case-insensitive literal string of 1–200 characters. `context` is an integer from 0 to 50 and defaults to 0. A time bound or text filter scans up to 1,000 records. Results return `text`, `scanned`, `returned`, `truncated`, and nullable `first`, `last`, `next` timestamps. At most 300 records are returned. Narrow the window for dense logs.

**Diagnosis.** `state` includes `status`, booleans `running`, `restarting`, `oomKilled`, nullable `exitCode`, `error`, nullable `startedAt` and `finishedAt`, and `restartCount`. `health` is null for containers without a health check. Otherwise it contains `status`, `failingStreak`, and up to three `recent` checks with `start`, `end`, `exitCode` and `output`. `logs` contains `scanned`, nullable `first` and `last`, and at most 40 summarized `errors`. Each error has a `sample`, `count` and nullable `first` and `last`.

**Failures.** JSON errors use `{ "error": "code" }`. HTTP 400 covers malformed bodies (`invalid-body`), targets (`invalid-target`, `app-id-required`), log filters (`invalid-since`, `invalid-until`, `invalid-after`, `invalid-pattern`, `invalid-context`) or an ID mismatch (`confirmation-mismatch`). HTTP 401 `sign-in-required` requires reauthentication. HTTP 403 `forbidden` means missing permission, expired or missing grant, or disallowed request context. HTTP 404 `not-found` means an unknown route or unavailable target. HTTP 409 `target-changed` means the target or preview is stale. Refresh and preview again. HTTP 429 `too-many-grants` means the active grant limit is reached. HTTP 502 includes `docker-unavailable`, `vos-request-failed`, `response-too-large`, or `upstream-unavailable`. Check VOS or Docker availability and reduce the log range when appropriate.

**Expert tool.** `vos_diagnostics` takes `query` with one of `inventory`, `status`, `logs`, `app-logs`, `diagnose`. For all except `inventory`, supply `id` with the target ID described above. It returns `status` and `body` from the corresponding read. A 503 `diagnostics-unavailable` means the VOS capability is absent. The tool has no write operations. Browser preview and confirmation are required for changes.
